KNN from scratch on Spark: 21.7 million distance computations.

No MLlib. No scikit-learn. The entire K-Nearest Neighbors algorithm — distance computation, neighbor selection, and voting — implemented using pure PySpark RDD primitives. 90.53% accuracy classifying six human activities from 561-dimensional sensor vectors, deployed identically on a laptop and on AWS EMR.

The problem

Human Activity Recognition (HAR) is a fundamental problem in wearable computing. Smartphones carry accelerometers and gyroscopes that capture motion at 50Hz — but classifying what a person is doing from that signal at scale requires a pipeline that can handle large-scale inference workloads without relying on pre-built ML libraries.

The constraint was deliberate: implement the entire KNN algorithm from scratch using only Apache Spark's RDD operations. No MLlib, no scikit-learn, no external ML library at any stage. The goal was to prove that a distributed classification pipeline can be built from first principles and deployed on a cloud cluster with zero code changes.

The dataset

The UCI Human Activity Recognition Dataset, created by Anguita et al. (2013), was collected from 30 volunteers aged 19–48, each wearing a Samsung Galaxy S II on their waist while performing six activities: Walking, Walking Upstairs, Walking Downstairs, Sitting, Standing, and Laying.

The raw 50Hz sensor signals were pre-processed into 561 features per 2.56-second window — time-domain statistics (mean, std, MAD, max, min, energy, entropy, autoregression coefficients) and frequency-domain features via FFT (mean frequency, skewness, kurtosis, energy bands). The result is a dense floating-point vector well-suited for distance-based classification.

System design
What I did
  1. Loaded and parsed the UCI HAR data. Feature matrices (X_train.txt, X_test.txt) and labels (y_train.txt, y_test.txt) read from local paths or S3, parsed into floating-point vectors, joined with labels using zipWithIndex(), and produced RDDs of (sample_id, feature_list, activity_label) tuples.
  2. Swept over K values for validation. Split training data 80/20 into sub-train and validation sets. Evaluated K ∈ {1, 3, 5, 7, 11} by broadcasting the sub-training data and classifying the validation set. Selected K = 11, which achieved a validation macro-F1 of 0.9872.
  3. Built the distributed KNN from scratch. The full training set (7,352 samples × 561 features ≈ 33 MB) is collected to the driver and shipped to every executor exactly once via sc.broadcast(). Each executor classifies its partition of test samples via RDD.map() — computing Euclidean distances to all training samples, sorting, selecting K nearest, and performing majority voting. No shuffle operation during inference.
  4. Implemented distance-weighted voting. Optional mode where each neighbor's vote is weighted by 1/distance (with epsilon 1e-9 to avoid division by zero), giving closer neighbors more influence on the classification.
  5. Deployed on AWS EMR. The same harsc.py script ran on a cloud cluster (EMR cluster j-148KLA9P02NS) with data on S3 — zero code changes required. Step completed successfully with Spark application final status: SUCCEEDED.
  6. Evaluated comprehensively. Per-class precision, recall, F1, confusion matrix, phase timing analysis, and comparison against the published SVM baseline by Anguita et al.
Architecture
Why it scales

The architectural insight is that KNN inference is embarrassingly parallel: each test sample's K nearest neighbors can be found independently of every other test sample. HARSC exploits this with Spark's broadcast-and-map pattern:

Analysis

Laying achieves the highest F1 (0.9972) because when a subject lies down, gravity dominates a single accelerometer axis — making it almost perfectly separable from every other activity.

Dynamic activities (Walking, Walking Upstairs, Walking Downstairs) achieve F1 between 0.87 and 0.92. They produce well-separated periodic inertial patterns. Walking Downstairs has the lowest recall (0.7976) — some downstairs steps are misclassified as general walking.

Sitting and Standing show the most confusion (F1 of 0.85 and 0.88). Both are static postures producing very similar sensor signals. The distinguishing features are subtle differences in trunk angle and minor postural shifts. Distance-weighted voting could further improve this separation.

The KNN result of macro-F1 = 0.9024 slightly exceeds the published SVM baseline of macro-F1 ≈ 0.89 by Anguita et al. — despite using no optimised ML library and no iterative training. The trade-off is inference cost: brute-force KNN is O(N·D) per test sample, but Spark's parallelism mitigates this for moderate-scale data.

Cloud deployment

The pipeline was deployed on AWS EMR (cluster j-148KLA9P02NS) with data stored in S3. The same harsc.py script ran on the cloud cluster with zero code changes — data paths switch from local to s3:// URI scheme and everything else remains identical. Spark application final status: SUCCEEDED.

The cloud run used a reduced configuration (K=5 only, 10% training data) for efficient validation under the course cloud environment. The canonical metrics (90.53% accuracy, 0.9024 macro-F1) were obtained from the complete local Spark run with the full training configuration.

Key finding

A from-scratch KNN implementation distributed over Spark RDDs is both feasible and competitive — exceeding the published SVM baseline without any ML library. The broadcast-and-map architecture gives linear scalability, and the same code runs identically on a laptop and a cloud cluster.
